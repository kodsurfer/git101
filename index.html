2. Ветки как параллельные версии идеи

Основная версия сайта остаётся стабильной, пока ты экспериментируешь.

Сейчас есть только ветка main — основная версия проекта.

Git ≠ GitHub

Git

Система контроля версий. Может работать полностью локально без интернета.

GitHub

Сервис для хранения Git-репозиториев, совместной работы, review и публикации проектов.

Аналогия:
Git — история версий.
GitHub — общее пространство команды.

4. Clone и Pull: как получить проект и обновления

Это два разных действия: один раз забрать проект и потом регулярно подтягивать изменения.

A
GitHub

Общий репозиторий команды.

$ repo: portfolio-site
main → commit #A12
⇄
D
Компьютер дизайнера

Локальная копия проекта.

$ пока пусто
git clone
git pull
git clone — первый раз скачивает репозиторий целиком. git pull — позже подтягивает новые изменения.

5. Pull Request как дизайн-review для кода

Ты сделал новую версию блока, показываешь команде, получаешь комментарии и только потом сливаешь в main.

#42 New hero section
feature/hero → main
Draft

Шаг 01
Открыть PR

Показать, какие изменения предлагаются.

Шаг 02
Получить review

Комментарий можно оставить прямо рядом с кодом.

Шаг 03
Merge

После проверки изменения попадают в main.
